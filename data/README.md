# Data contract

The training pipeline expects a CSV with these columns:

| Column | Meaning |
|---|---|
| `district` | Supported Berkane district name |
| `property_type` | `apartment`, `house`, or `villa` |
| `condition` | `to_renovate`, `good`, `renovated`, or `new` |
| `area_m2` | Property area in square metres |
| `bedrooms`, `bathrooms` | Positive room counts |
| `floor` | Floor number; use `0` for ground-level houses |
| `age_years` | Approximate property age |
| `balcony`, `garden`, `garage`, `air_conditioning` | Binary `0`/`1` flags |
| `price_mad` | Observed sale or asking price in Moroccan dirhams |

`demo_properties.csv` is generated by `scripts/generate_demo_data.py`. It is synthetic and exists only to exercise the software. It is not evidence about the Berkane housing market.

Real data should be stored under `data/private/`, which is ignored by Git. Before training a market-facing model, document the source, collection date, consent or usage rights, cleaning rules, and the difference between asking and transaction prices.
